# sites-hub: instructions for agents

This repo is the control center for a set of static websites on GitHub Pages. **Agents make all code changes; the owner does not read code.** Optimise for clear summaries to the owner in plain language, and keep the repo self-explanatory for the next agent.

## Hard rules
1. **This repo is PUBLIC.** Never commit secrets, tokens, emails, real names, phone numbers, addresses or anything private. `python3 scripts/check.py` scans for token patterns; run it before every commit.
2. **GitHub only.** No backend, no other clouds, no databases, no paid services. Static HTML/CSS/JS only.
3. **No custom domains for now.** Every new site is a folder under `sites/<name>/` and appears as a card on the hub main page (`https://msather.github.io/sites-hub/`).
4. **Ask before big work.** Before building any new site or any large change (new feature, restructure, workflow change, anything touching many files), interview the owner: ask several questions (purpose, audience, look and feel, content, scope) and wait for answers. Skills: `.claude/skills/new-site`, `.claude/skills/large-change`. Small fixes (typos, copy tweaks) need no interview.
5. **Never hand-edit generated or registry files.** `sites.md` rows are written by `scripts/new_site.py`; the hub index is generated by `scripts/build_hub.py` into `_site/` (git-ignored).
6. Report results faithfully: what worked, what failed, with evidence.

## Layout
- `sites/<name>/`: one folder per site (plain HTML/CSS, relative links only).
- `templates/site-starter/`: template with `{{NAME}} {{TITLE}} {{DESCRIPTION}} {{BASE_URL}} {{YEAR}}` placeholders.
- `sites.md`: registry table (source of truth for the hub index).
- `scripts/`: `new_site.py`, `build_hub.py`, `check.py`, `sites_md.py` (stdlib Python only).
- `.github/workflows/`: `create-site.yml` (manual), `pages.yml` (deploy), `check.yml`.
- `docs/`: `architecture.md`, `agents.md`.

## How to do common things
- **New site:** follow `.claude/skills/new-site`. Preferred: trigger the **Create site** workflow (`workflow_dispatch`, inputs `name`, `description`). Fallback: `python3 scripts/new_site.py --name X --description "..."`, then commit.
- **Edit a site:** change files in `sites/<name>/`, run `python3 scripts/check.py`, commit, push to `main`.
- **Deploy:** (needs Settings → Pages → Source = GitHub Actions, set once by the owner) see `.claude/skills/deploy-site`. Pushing to `main` deploys automatically via `pages.yml`; the Create site workflow also deploys.

## Conventions
- Branch `main` is deployable. Commit messages: short imperative summary.
- Sites must work on phones, support light/dark (`prefers-color-scheme`), and have a `<title>` and meta description.
- Use relative URLs inside `sites/<name>/` because they are served from a sub-path.
- When you learn something future agents need, add it to this file or `docs/`.
